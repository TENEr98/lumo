# Lumo — правила проекта для Claude Code

Lumo (рабочее название) — компактное приложение для macOS, iOS и iPadOS: снимки экрана с редактором, запись экрана, лёгкий видеомонтаж, архиватор и менеджер буфера обмена с единой библиотекой и синхронизацией через iCloud пользователя. Ты — исполнитель проекта: пишешь весь код, тесты и документацию. Владелец продукта ставит задачи, проверяет сборки на устройствах и принимает решения.

## Где что лежит

- `docs/bft.md` — бизнес-функциональные требования. Каждое требование имеет код (SCR-01, IMG-05, ARC-04 …). Это источник истины по функциям.
- `docs/plan.md` — план проекта: этапы, спринты, контрольные точки.
- `docs/kb/` — база знаний: архитектура, модель данных, ограничения Apple, глоссарий, источники. Начинай с `docs/kb/README.md`.
- `docs/decisions.md` — журнал архитектурных решений (ADR). Не противоречь принятым решениям молча.
- `docs/progress.md` — текущее состояние: что сделано, что в работе, что отложено.
- `core/` — Rust-воркспейс (ядро `lumo-core`).
- `apple/` — проект Xcode: приложения macOS и iOS/iPadOS, расширения.

## Архитектура в одном абзаце

Rust-ядро делает всё, что не зависит от платформы: хранилище SQLite с поиском FTS5, архивы, историю буфера (модель и правила хранения), растровые операции (размытие, пикселизация, склейка, сжатие, GIF), миниатюры и сериализацию записей для синхронизации. Swift делает всё, что касается системы: интерфейс SwiftUI/AppKit, ScreenCaptureKit, ReplayKit, AVFoundation, Vision, PencilKit, CloudKit. Мост — UniFFI, поставка ядра — XCFramework. Подробно — `docs/kb/02-architecture.md`.

## Порядок работы над каждой задачей

1. Прочитай этот файл, нужный раздел `docs/bft.md` и `docs/progress.md`.
2. Возьми ровно один код требования или одну проверку этапа 0. Сформулируй, как будет проверен результат, опираясь на критерии приёмки БФТ (раздел 13).
3. Для логики ядра — сначала тесты, затем код. Собери ядро и обе оболочки, прогони все тесты.
4. Если результат нельзя проверить автоматически (системные разрешения, захват экрана, запись, синхронизация между устройствами, ощущение от интерфейса) — остановись и выдай владельцу сценарий ручной проверки по шаблону из скилла `acceptance-testing`.
5. После подтверждения — коммит с кодом требования в начале сообщения (`ARC-04: автоопределение CP866 в именах ZIP`) и запись в `docs/progress.md`.

## Агенты проекта и когда их звать

| Агент | Модель | Зона ответственности |
| --- | --- | --- |
| `architect` | opus | Решения между слоями, контракт UniFFI, модель данных, ADR, разбор спорных требований |
| `rust-core-engineer` | sonnet | Код и тесты в `core/` |
| `apple-platform-engineer` | opus | ScreenCaptureKit, ReplayKit, CloudKit, буфер обмена, разрешения, entitlements, песочница |
| `media-engineer` | opus | Запись, монтаж и экспорт видео на AVFoundation |
| `swiftui-engineer` | sonnet | Экраны, редактор изображений, библиотека, локализация интерфейса |
| `test-engineer` | sonnet | Автотесты, сценарии ручной проверки, сверка с критериями приёмки |
| `reviewer` | sonnet | Независимое ревью перед завершением задачи и спринта; только чтение |
| `release-manager` | sonnet | TestFlight, App Store Connect, тексты, метки конфиденциальности, пояснения для проверки |
| `docs-keeper` | haiku | `progress.md`, база знаний, журнал изменений |

Правило: задача, которая трогает и ядро, и Swift, начинается с `architect` (контракт), затем идут исполнители, в конце — `reviewer`.

## Запреты

- Никаких сторонних SDK аналитики, рекламы и отслеживания. Приложение в App Store заявлено как «Данные не собираются».
- Никакого FFmpeg и зависимостей с лицензиями GPL, LGPL-со-статической-линковкой, AGPL. Перед добавлением любой зависимости проверь лицензию и запиши её в `docs/kb/10-dependencies.md`.
- Не создавать RAR-архивы и не использовать исходники UnRAR для чего-либо, кроме распаковки.
- Не держать пользовательские данные на серверах разработчика: только локально и в частной базе CloudKit пользователя.
- Не помечать требование выполненным без пройденного критерия приёмки.
- Не менять БФТ и не отступать от ADR без явного решения владельца. При конфликте с реальностью платформы запиши предложение в `docs/decisions.md` со статусом «предложено» и спроси.
- Не придумывать поведение системных API Apple. Если не уверен — проверь документацию (WebFetch developer.apple.com) или сделай минимальный эксперимент и сообщи результат.

## Команды

Заполняются в задаче 0.2 этапа 0, когда появится скелет репозитория:

- Сборка и тесты ядра: `cargo test --workspace` (из `core/`)
- Сборка XCFramework: `./scripts/build-xcframework.sh`
- Сборка Mac-приложения: `xcodebuild -scheme Lumo-macOS build`
- Сборка iOS-приложения: `xcodebuild -scheme Lumo-iOS -destination 'generic/platform=iOS Simulator' build`
