# Синхронизация через CloudKit

## Основа

- Контейнер `iCloud.<bundle-prefix>.lumo`, **частная** база пользователя, собственная зона `LumoZone`.
- `CKSyncEngine` (iOS 17 / macOS 14): движок сам планирует отправку и получение; мы реализуем делегата — отдаём ожидающие изменения и применяем входящие.
- Состояние движка (`CKSyncEngine.State.Serialization`) сохраняется на диск после каждого события и передаётся при создании движка.
- Требует платного членства Apple Developer и возможности iCloud в entitlements обеих целей.

## Типы записей

| Тип | Поля | Вложения |
| --- | --- | --- |
| `LibraryItem` | kind, title, tags, createdAt, modifiedAt, sourceApp, device, ocrText*, version, deleted | `original` (CKAsset), `thumbnail` (CKAsset) |
| `EditorProject` | itemRef, objectsJSON*, version | — |
| `ClipItem` | kind, text*, url*, sourceApp, createdAt, pinned, version | `payload` (CKAsset для изображений и файлов) |
| `Settings` | ключ-значение настроек | — |

`*` — поля в `record.encryptedValues`: шифруются ключами из связки ключей iCloud пользователя.

## Правила

- Идентификатор записи = UUID элемента в ядре; ядро — источник истины локально.
- Сериализацию и правила слияния делает крейт `sync-model`; Swift только переносит байты.
- Слияние: простые поля — побеждает больший `modifiedAt`; `EditorProject` при одновременной правке — сохраняются обе версии, вторая как копия (LIB-06).
- Удаление — мягкое (`deleted = true`) с окончательным удалением через 30 дней (LIB-04).
- Скрытые элементы буфера (concealed) никогда не создают записей.

## Состояние аккаунта

Проверять `CKContainer.accountStatus()` при старте и по уведомлению `CKAccountChanged`. Нет аккаунта или iCloud выключен для приложения — всё работает локально, в настройках понятное сообщение (LIB-07). Смена аккаунта — локальные данные не отправляются в чужой аккаунт без подтверждения пользователя.

## Ошибки, которые обязательно обработать

`quotaExceeded` (сообщить, LIB-09), `networkUnavailable`/`networkFailure` (повторить позже), `serverRecordChanged` (слияние), `zoneNotFound` (пересоздать зону), `userDeletedZone` (спросить пользователя), `limitExceeded` (разбить пакет).

## Проверка

1. Mac и iPhone с одним Apple ID: элемент, созданный на одном, появляется на другом меньше чем за минуту.
2. Режим полёта на iPhone, правка, включение сети — изменение доезжает.
3. Одновременная правка проекта на двух устройствах — обе версии сохранены.
4. Выход из iCloud — приложение работает, синхронизация показана как выключенная.
