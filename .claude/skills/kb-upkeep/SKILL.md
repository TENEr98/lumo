# Ведение базы знаний

## Файлы

| Файл | Что там | Кто пишет |
| --- | --- | --- |
| `docs/progress.md` | Состояние задач по спринтам | после каждой задачи |
| `docs/decisions.md` | ADR — архитектурные решения | `architect` |
| `docs/kb/*.md` | Факты о проекте и платформе | все агенты, через `docs-keeper` |
| `docs/kb/07-glossary.md` | Термины | при появлении термина |
| `docs/kb/10-dependencies.md` | Зависимости и лицензии | при добавлении зависимости |
| `docs/test-scripts/*.md` | Сценарии ручной проверки | `test-engineer` |

## Шаблон ADR

```markdown
## ADR-NNN: <решение одной фразой>

Статус: предложено | принято | заменено ADR-MMM
Дата: ГГГГ-ММ-ДД

Контекст: какая проблема, какие ограничения.
Решение: что выбрали.
Альтернативы: что рассматривали и почему нет.
Последствия: что становится проще, что сложнее, что проверить.
```

## Строка в progress.md

`| ARC-04 | готово | 2027-01-30 | a1b2c3d | Mac macOS 15, iPhone iOS 18 | test-scripts/ARC-04.md | — |`

Колонки: код, статус (в работе / на проверке / готово / отложено), дата, коммит, где проверено, сценарий, примечание.

## Правила записи фактов

- Один факт — одна строка или короткий абзац, с источником (ссылка, коммит, эксперимент).
- Если факт опровергнут — исправь, а не добавляй противоречащий.
- БФТ и принятые ADR не правятся без решения владельца.
