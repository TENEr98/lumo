# Журнал архитектурных решений (ADR)

Шаблон и правила — скилл `kb-upkeep`. Решения со статусом «принято» не меняются без решения владельца.

## ADR-001: Rust-ядро + нативные Swift-оболочки

Статус: принято · Дата: 2026-10-29

Контекст: нужны Mac, iPhone и iPad; захват экрана, iCloud и расширения доступны только через фреймворки Apple; архивы, хранилище и обработка данных одинаковы везде.
Решение: ядро `lumo-core` на Rust, мост UniFFI, поставка XCFramework; интерфейс и системные API — Swift (SwiftUI + AppKit).
Альтернативы: всё на Swift (проще сборка, но архивы и общая логика без выигрыша Rust; владелец хочет Rust); Tauri/кроссплатформенный UI (нет доступа к расширениям iOS, хуже нативность).
Последствия: две экосистемы сборки, нужен скрипт XCFramework; логика данных тестируется быстро и одинаково.

## ADR-002: AVFoundation вместо FFmpeg

Статус: принято · Дата: 2026-10-29

Решение: запись, монтаж и экспорт видео — AVFoundation/VideoToolbox/Core Image; GIF — в Rust-ядре.
Причина: аппаратное ускорение, маленький размер, нет лицензионных рисков FFmpeg в App Store.
Последствия: набор форматов ограничен тем, что умеет система; этого достаточно для записей экрана.

## ADR-003: Синхронизация только через частную базу CloudKit пользователя

Статус: принято · Дата: 2026-10-29

Решение: CKSyncEngine, зона `LumoZone`, чувствительные поля в `encryptedValues`; своих серверов нет.
Последствия: нулевые серверные расходы, данные в квоте пользователя; требует платного членства Apple Developer; без iCloud приложение работает локально.

## ADR-004: RAR — только распаковка

Статус: принято · Дата: 2026-10-29

Причина: лицензия UnRAR запрещает воссоздавать алгоритм сжатия. Создание архивов — ZIP и 7z.

## ADR-005: Mac — основная платформа, iPhone и iPad — спутники

Статус: принято · Дата: 2026-10-29

Причина: ограничения iOS на захват чужого экрана и фоновый доступ к буферу. Порядок разработки: ядро → Mac → синхронизация → iPhone → iPad (v1).

## ADR-006: Общий SwiftUI-код для всех платформ

Статус: принято · Дата: 2026-10-29

Решение: экраны в пакете LumoKit пишутся на SwiftUI сразу для Mac и iOS; AppKit — только для оверлеев, панелей и строки меню.

## ADR-007: Без сторонних SDK аналитики, рекламы и отслеживания

Статус: принято · Дата: 2026-10-29

Причина: обещание «Данные не собираются», компактность. Диагностика — только встроенные механизмы Apple с согласия пользователя.

## ADR-008: Название Lumo — рабочее

Статус: принято · Дата: 2026-10-29

Название уже используется другим продуктом (риск R5). Финальное название выбирает владелец до беты; в коде использовать нейтральные идентификаторы, которые легко переименовать (bundle id задаётся при оплате членства).
